# 借道 · 下一阶段试玩

目标：把真实主页的链接、标题与按钮借来做一场可调路线的弹射游戏；博客保留真实文章，成为她的阅读与修改记录。

方向：保留原站纸面、手写/衬线字体与现有 WAAPI/FLIP。她直接借标题说话；链接仍是链接，不做卡片菜单。蓝绿表示连接，紫色表示可调反射面，杏色表示终点；反馈只发生在碰撞处。游戏把原导航节点展开到整页，收起时原节点归位。

路线：先学反射，再借链接穿行，最后跨越一张长页面。玩家拖动横条、调角度、拖圆点瞄准；失败留下上一条轨迹。她会扶正/加长实际横条。完成三条路线后才邀请安装「链接刹车」，新版在传送出口停球，允许第二次瞄准；旧版的连续弹射仍可从真实博客记录找到。

文件：`p34-home.js/css` 负责真实主页与对白；`p34-pinball.js` 负责 DOM/输入/绘制；`p34-pinball-physics.js` 为固定步长物理；`p34-play-state.js` 为独立、兼容旧 cookie 的本轮进度。博客 `paper-blog.js/css` 与 Astro 创作记录独立实现，不挂主页空间。不改聊天/商店或旧存档意义。

## 本地试玩

两个仓库使用 `feat/p34-native-play`，放在同一父目录。只推开发分支，不部署生产。

```powershell
# sayori-blog
pnpm exec astro build --outDir .codex-tmp/p34-native-build

# sayori-home，保持进程运行
node scripts/preview-p34.mjs
```

主页：`http://127.0.0.1:8970/?paper=0617`。博客：`http://127.0.0.1:8971/?paper=0617`。
预览服务只在响应中把两站地址改成本机地址，源码保持正式域名；两个端口共用本机 cookie。生产继续使用 `.sayori.org` 的玩家独立 cookie，不新增后端或 Cloudflare 资源。

首次来访，扶住正在掉落的「社交账号」，再答应试玩。紫色横条可拖动；选中后用滑杆或 Q/E 旋转，方向键挪位置。拖光点瞄准、松手发射，也可以用方向键和空格。第二条路要调整反射高度，第三条要把两段路线接起来。暂停、重试和收起随时可用。

完成第一版三条路后，她才邀请安装「链接刹车」。出口会接球，让玩家重新瞄准；以前一口气弹完的节奏变了。更新保留原横条与成绩。博客的《给链接装个刹车》留下旧稿入口；发现后新增旧稿话题，不把版本做成主题切换按钮。

## 文件与边界

主页新入口由 `paper-material.js` 挂载 `p34-home.js`；博客 `paper-blog.js` 独立挂在 Astro 生命周期中。旧统一全屏空间不再接管这两个入口；原 `p34-motion` 与世界/剧情编解码保留，商店仍依赖旧共享模块，因此没有连带删除它们。商店指向博客的旧 `#blog` / 四篇 `#note-*` 链接转到新的真实记录，`#space` / `#play` 返回主页。没有恢复调查中心或旧三小游戏。

新进度在 `p34_routes`；`met` 是主页相遇，`first/second` 是三路线完成位，`edition` 是当前更新，`archive` 是旧稿发现，`best` 是成功路线的最长反弹数。博客和主页各携带一份同格式小模块。

博客记录由 `src/data/p34-notes.ts` 和 `src/pages/notes/` 生成，不进入会被同步覆盖的文章目录。`herProfile.website` 暂为空，确定域名后可用来链接记录署名。Twikoo 原有 nick/link/avatar 和文章 path 不变；正式评论身份仍需作者亲自设置。
