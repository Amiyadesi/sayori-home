# Amiya 的未保存版本

## 作品约定

这是一款讲述 Amiya_desi 的跨网站个人叙事 ARG。玩家寻找一部缺少最后一幕的游戏，逐渐认识做游戏、学技术、折腾网站、写作、怀疑又重新动手的同一个作者。不是虚构机构借用作者经历，也不是把人生压缩成失败与自救。

目标主线 35–60 分钟，支线约 10–20 分钟；这是设计预算，须由首次接触作品的人试玩验证。不能以自动通关速度证明时长。

本作新增自述、版本留言、关卡、网页异常均为改编创作；不是原话、历史网页取证或实际未公开项目。原文章保持原样。界面开场和每页「作品说明」明确边界；不依赖现实中的紧急事件制造压力。

## 七个核心问题

1. 玩家是偶然路过博客的访客，接受一次匿名试玩邀请。
2. 一条游戏介绍显示作者为 Amiya，但「关于作者」同时存在三个互不兼容版本；它们都链接同一部没有结尾的游戏。
3. 秘密不是作者失踪：这些版本分别保留了做出第一件东西的快乐、掌握工具的自信、事后观察自己的严厉，却在争夺唯一的署名。现在的作者被挤成空白。
4. 玩家通过试玩、叠读文章、连接兴趣足迹、削减开发范围、核对不同媒介证据、完成最终关卡推进。
5. 主页展示「希望别人看到的我」；博客容纳修订和迟疑；可玩的游戏暴露言语不能代替的设计决定；声音玩具让表达本身成为奖励。
6. 情绪：好奇 → 小小的成就 → 热闹与荒诞 → 失去控制 → 亲自动手 → 被认真看见。忧伤不能占满全程。
7. 冲突是不同阶段都试图凭一个特征代表完整的作者。高潮是亲手发布一个能走到结尾的关卡。结尾由玩家选带的两件纪念物改变回应，所有路线都允许修改和重玩。

## 玩家流程与线索充分性

### 博客 /unsaved/：一篇没有写完的发布说明（4–6 分钟）

独立短文、游戏封面和异常署名。玩家打开发布说明，发现同一个名字出现三次；无密码。接受试玩后进入另一个真实 origin 的主页，在那里打开三份介绍。每条跨站链接携带只含游戏进度的片段令牌。外站故障时可复制存档，稍后继续。

### 主页 /unsaved/：三份关于我（4–6 分钟）

「起点」「工具箱」「旁观者」三个版本的名片、自述和各自的缺口。玩家逐个检查，发现各自把一个词删掉。不是选正确人格；三者都记录进线索册。旧作入口指向 /unsaved/first/。

### 主页 /unsaved/first/：先让方块走起来（5–8 分钟）

可键盘/触屏操作的回合制像素小关卡：移动、推箱到开关、打开门到达旗帜。无反应速度要求，可一步撤销、重开。第一次成功让一段作者改编留言与纸条显现，纸条指出博客文章的修订层。玩家体验「粗糙但能玩」的快乐。可听到自制短音效。

### 博客 /unsaved/margins/：后来补上的话（6–9 分钟）

三个写作切面：理性、能力、绕路。对照早期断言、后来经历和补写段落。每页有两张候选边注，选择真正回应证据的那张，并指出相关证据；不是要求赞同乐观观点。错误反馈解释缺少的证据，不扣分。完整页仍保留旧字，不能以新话删掉旧我。

### 主页 /unsaved/links/：我怎么会跑到这里（5–8 分钟）

六个兴趣节点：游戏、AI、社区、服务器、网站、小作品。把来源与结果成对连接，恢复一条有依据的关系链。每个节点可查看当时的简短记录；博客边注提供最后一条「网站回到作品」的证据。展示探索并非全是逃避。完成后出现被遗漏的「作者」手写签名及 Jam 项目入口。

支线 /unsaved/room/：八音玩具、原创音色、小房间便签。尝试任意四个不同音符解锁笑话与纪念物，无需听力或音频。没有第三方角色音频。

### 主页 /unsaved/jam/：还剩六小时（7–10 分钟）

时间是六格规划预算，不是真实倒计时。模块包括移动、桥、终点、撤销、Boss、商店、日常任务。玩家读取关卡需求，剪去无法服务目标的模块，以 ≤6 格预算保留能通关的组合，再实际试玩。缺少模块会在关卡对应位置说明原因。编辑与试玩可反复切换。通关后显示一份虚构提交差异：删去不等于这段经历没发生。

### 博客 /unsaved/shelf/：谁能署名（4–6 分钟）

三个自我版本各自提出不完整结论。玩家把实际玩过/读过的证据钉给对应结论：早期的成功、工具之外的连接、亲自动手的取舍。每个版本有完整回应，停止争夺唯一身份；不是替作者做心理诊断。回到主页的空白画面完成最后一次试玩。

### 主页 /unsaved/end/：这一页，留给现在（4–6 分钟）

从「第一面旗」「工具箱」「边注」中选择两件纪念物，点亮对应的旧窗口标记，改变最后场景的标题、装饰及后记。角色沿共同保留下来的路走到旗帜。三种后记分别偏向继续做、把故事分享出去、留出空白；无真/坏结局排名。支线纪念物加入额外末尾笑话。最后给出原创来源和作者可编辑的回应，不虚构真人收到实时通知。可导出自己的纯文本游玩纪念/存档，或回访别的结尾。

## 视觉与声音

共用「未保存圆点」与手工像素方块，避免各页面像同一个后台换皮。

- 博客：偏白纸 `#f6f7fb`、墨蓝 `#29334b`、朱红编辑笔 `#ba3e55`；中文宋体正文、无衬线边注。宽留白与可折叠正文。
- 名片站：雾紫 `#ece8f5`、深紫 `#322650`、珊瑚 `#c74862`；巨大中文标题与错位叠页，旧浏览器标签是可操作导航。
- 旧作：靛蓝 `#23294f`、湖水 `#9be5df`、黄 `#ffe5a0`；真实可玩的像素场景占视觉中心。
- 编辑器：石板蓝 `#273244`、浅灰 `#e9edf5`、蓝紫 `#bca4fa`；预算、关卡、操作是主层级，不伪造终端黑客氛围。
- 结尾：淡杏 `#f7ded0` 的桌面与靛蓝棋盘，纪念物点亮旧窗口标记，留白大于信息。

系统字体，无外部字体请求。声音由 Web Audio 合成，默认关闭、手动启用，有等价文字反馈。原生按钮、焦点轮廓、最小 44px 操作区、减少动画偏好、320px 单列。动画只回应操作，无闪烁、强制等待和浏览器权限请求。

## 技术与跨站存档

选原生 ES Modules + 静态 HTML：两个已有站点均可直接托管，不引入 Svelte/新构建系统或后端身份。Astro 仅负责原博客，ARG 作为 public 下独立文档，不受 ClientRouter 生命周期影响。博客入口链接用整页导航。

源码主份位于 home 的 `public/unsaved/`；blog 的共享运行文件由显式同步脚本复制并提交。生产构建不跨仓库拉取游戏代码；单独的两份 PR 共同交付。每页按 `data-scene` 装配交互，故事在 authored HTML 中，可直接编辑。

每个 origin 用同名 localStorage 保存独立副本。跨站链接带 `#u=<base64url JSON>`；仅运行 ID、完成节点、已收集线索、提示等级、结尾记录，无姓名、笔记、认证信息。入口验证大小、版本、字段、节点依赖；同一局单调合并，外来的另一局必须明确选择，损坏数据不覆盖本地。导入/导出 JSON 和复制粘贴码互为备份。令牌可被玩家修改，这是单机游戏存档，不是认证凭据。

跨域不会实时同步已打开的旧标签：通过带票链接回来或重新导入；本域 storage 事件更新进度。重开建立新运行 ID，旧局不会自动复活。未完成的棋盘尝试刷新复位，已完成节点/线索/提示保存；界面说明此范围。localStorage 不可用时显式警告，仍能通过令牌和文件继续。

只接受配置内确定目的地，不把令牌字段当导航 URL。URL 片段接收后清除；游戏无埋点、外部媒体、真实评论或请求发送功能。资源缓存要求重新验证，防止两站更新导致旧协议常驻。
