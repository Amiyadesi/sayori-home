# 试玩《Amiya 的未保存版本》

先打开博客里的发布说明，再顺着链接去另一张书桌。主角始终是 Amiya：三份自我介绍、一个能玩的方块、绕出去又接回来的兴趣，以及一次真正需要删东西的 Jam。

这是可从入口走到三种后记的首轮作者试玩版。主线目标仍为 35–60 分钟；首次玩家时长和作者表达尚待验收，不能据自动通关认定完成了最终发布目标。

## 本地打开

需要 Node.js 22+；游戏预览本身不需要 npm 安装。把两个 feature 分支分别放在相邻的 `sayori-home`、`sayori-blog` 目录。

在 home 仓库运行：

```sh
node scripts/sync-unsaved.mjs --check
node scripts/preview-unsaved.mjs
```

打开 **http://127.0.0.1:4321/unsaved/**。主页会在 **4322** 打开；两个端口是不同 origin，确实各有独立存储。不要把二者合在同一个端口验证存档。

如果 blog checkout 不相邻，两个脚本都接受其绝对路径作为第一个参数。端口占用会报错，不会杀掉其他进程。按 Ctrl+C 停止自己的预览。

这个轻量服务器只提供 `public`，不渲染 Astro 博客首页。正常博客首页回归要使用其构建结果。预览绑定回环地址，不是公开部署。

## 写在哪里

- 主线设计、来源与范围：`DESIGN.md`。
- 作者通关答案（剧透）：`WALKTHROUGH.md`。
- 实测结果与未通过项目：`QA.md`。
- home 的 `public/unsaved/`：关于我、旧作、兴趣图、Jam、音乐房间、结尾；运行代码也以这里为准。
- blog 的 `public/unsaved/`：发布说明、文章边注、证据回应。
- `scripts/sync-unsaved.mjs`：只复制 `app.js`、`core.js`、`sites.js`、`game.css`，不覆盖各站独有的 HTML。

改剧情直接编辑对应 HTML；改玩法编辑 home 的运行代码后执行同步脚本并提交两边副本。四个共享文件必须同版；没有运行时跨仓库下载、数据库或账户。

## 存档怎么工作

自动保存完成节点、已读线索、提示层级、已解锁后记。**未完成的棋盘与连接尝试在刷新后复位**。每页线索册都说明了范围。

跨站链接用 `#u=` 携带版本 1 的 JSON 编码，接收后清除 URL 片段。同一局只合并新增记录；另一局需要玩家确认。编码不是加密或防作弊，也没有真实身份字段。

玩家可导出 JSON 或复制携带码，在另一浏览器导入。存储受限时页面明确警告，内存与跨站携带仍可用。不要用裸站点链接代替游戏内链接来测试跨域进度；两个已开的跨域标签不会实时同步。

## 发布前的两个 PR

仅使用已确认的 `sayori.org` 与 `blog.sayori.org`，没有新的 DNS 或服务要求。本次只提交 feature 分支与 **draft PR**；main 工作流会部署，所以不合并、不手动触发部署。

作者同意发布后再执行：

1. 作者核对改编台词与来源、首次玩家试玩时长、提示与趣味性。若主线不足 30 分钟，继续增加有意义的调查与操作，不能靠等候或重复题填充。
2. 两个 PR 共同审阅；先合入并验证 home 目的页面，再发布 blog 入口。home 页脚在这个短窗口会先指向尚未发布的入口，因此应在同一维护窗口完成两站，或临时不发布入口改动。
3. 验证两站 `/unsaved/` 页面、共享脚本版本、真实跨域携带、博客整页导航和 service worker 更新。完整浏览器验收脚本记录在 QA。
4. 保留上一版静态资源和存档版本；回退两站同一版。不要删除用户 localStorage。以后改变存档协议时，须提供迁移或显式兼容提示。

未配置任意 Cloudflare 预览域名自动配对：`sites.js` 对生产固定域名和本地两端口明确映射。若另建远程预览，先明确两个地址并调整映射，避免预览跳回生产。

## 资源与现实边界

关卡图形与布局用原创 CSS；音效为 Web Audio 正弦合成，默认静音。系统字体，无外链字体、采样、追踪代码、远程模型请求或发送消息的操作。

故事只取材于公开文章；所有新增对白、网页版本、关卡和提交片段都是改编。真实文章不改写；原作只链接，不复制第三方角色、音频和图片。无需访问私人系统或联系任何真人。页面不进入 Pagefind 搜索，标记 noindex；这不是访问权限控制，游戏源代码仍公开可读。
